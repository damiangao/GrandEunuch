# GrandEunuch（大内总管）PWA 产品设计 v1

> 本文确定 GrandEunuch 的 V1 客户端产品形态与最小体验范围。Agent / Runtime 语义、工具契约与可靠性约束仍以 [GRAND_EUNUCH.md](./GRAND_EUNUCH.md) 为准；本文不修改其中的决策权边界。

## 一、已确认的产品决策

GrandEunuch V1 是一个**私密对话型 PWA**。

用户可以在浏览器中使用，也可以将其安装到桌面或手机主屏。它不是终端工具、桌面原生 App 或即时通信软件机器人；现有 CLI REPL 仅保留为开发与验证入口。

产品以持续私聊为唯一核心界面，向用户提供两类能力：

1. **事务总管**：记录并跟进协作承诺、待确认结果、责任与时间点；仅在重新判断后确有必要时提醒用户。
2. **灵感总管**：在用户主动对话时，从已有想法中关联、整理并提出可能的方向。

## 二、V1 最小闭环

V1 的成功标准是用户可以完成下列端到端流程：

1. 打开 PWA，在私密对话中发送一条消息；
2. Agent 以 `user_message` Trigger 处理消息并返回回复；
3. Agent 可以持久化及检索与该用户隔离的记忆；
4. 用户刷新或重新打开应用后，记忆仍然可供 Agent 在后续对话中使用；
5. 对事务性事项，Agent 可以创建未来 Wake；到期后 Runtime 以 `scheduled_wake` Trigger 重新运行并决定提醒或静默；
6. 若 Agent 决定提醒，用户最多收到该 Wake occurrence 对应的一次可见提醒；
7. 创意内容只出现在用户主动发起的对话回复中。

## 三、界面范围

### 3.1 私密对话页

V1 的主页面是单一对话页，至少包含：

- 历史消息流；
- 消息输入与发送；
- Agent 正在处理、完成或失败的可观察状态；
- 普通文本回复与系统可理解的失败提示；
- 在浏览器支持时的 PWA 安装入口。

不在 V1 范围内：多频道、群聊、联系人、任务看板、日历视图、复杂记忆浏览器或人工编辑 Agent 推理过程。

### 3.2 提醒与通知

V1 只提供**应用内提醒**：事务性 Wake 到期、且 Agent 决定产生用户可见效果时，提醒应写入并显示在对话上下文中。

V1 不请求浏览器通知权限，不实现浏览器系统通知、Web Push 或任何后台推送。用户未打开 PWA 时不会立即收到提醒；下次打开应用后，已产生的提醒必须仍然可见。

创意内容不得通过任何提醒或通知机制主动展示。

### 3.3 创意内容的被动性

灵感和创意建议只能由 `user_message` Run 产生。它们不得：

- 创建用于主动推送灵感的 Wake；
- 由 `scheduled_wake` Trigger 发起；
- 通过浏览器通知主动展示；
- 因用户长时间未使用产品而主动发送。

这项规则适用于前端、服务端和 Runtime 的所有交付层。

## 四、客户端与 Runtime 的边界

PWA 是 Trigger 和用户可见效果的适配层，不参与业务判断。

| 场景 | PWA / 服务端适配层职责 | Runtime / Agent 职责 |
|---|---|---|
| 用户发送消息 | 验证会话身份，提交原始消息，创建 `user_message` Trigger，呈现 Run 状态与回复 | Runtime 组装 Run Input；Agent 理解意图、决定是否调用工具及如何回复 |
| 到期 Wake | 可靠接收调度事件，并在 Agent 已决定产生效果后展示对话提醒或发送通知 | Runtime 验证 occurrence、取消和遗忘状态；Agent 重新判断提醒还是静默 |
| 记忆 | 不预先挑选或解释记忆；仅在用户明确操作时展示可授权的数据 | Agent 决定检索、保存、修订和遗忘；Runtime 保证隔离、持久化和并发安全 |
| 通知 | 请求授权、保存订阅/偏好、发送不含敏感详情的通知 | 不根据通知渠道擅自改变事务判断 |

客户端、服务端适配层和 Runtime 都不得把消息内容预先分类为“事务”或“灵感”，也不得为此安排固定工具流程。该判断始终属于 Agent。

## 五、隐私与数据边界

V1 的交互前提是私密对话，设计应遵守：

- 每次请求都必须关联一个可信的用户身份与会话边界；
- Memory、Wake、消息记录和通知订阅必须按用户隔离；
- 不接入群聊、邮件、日历或其他外部内容源；
- 不代表用户向任何第三方发送消息；
- 通知内容默认最小化，避免在锁屏或共享设备上泄露协作和灵感细节；
- `memory.forget` 完成后，关联内容、索引、派生摘要和 Wake 必须按 Runtime 契约不可经正常产品路径恢复。

## 六、明确不做

以下内容不属于 V1：

- 即时通信软件机器人或 OpenClaw 式渠道接入；
- 原生桌面客户端；
- 多人协作、群聊和共享记忆；
- 自动读取或同步邮件、日历、聊天记录；
- 主动代用户联系他人；
- 创意内容推送、每日灵感简报或基于沉默的主动唤醒；
- 为事务或灵感新增专用 Runtime 工作流、Trigger 或工具。

## 七、V1 部署与身份决策

V1 是**单用户、本地运行的 MVP**：PWA 前端、Agent 服务、SQLite 数据库和 Wake 调度器都运行在用户自己的设备上或其自行控制的私有环境中。

- 不提供账号注册、登录、多租户或云端托管；
- 单实例只有一个使用者，因而不在 MVP 中实现多用户身份体系；
- SQLite 数据保存在本地实例，V1 不支持跨设备同步；
- 服务只应监听本机回环地址，除非用户明确自行配置私有网络访问；
- 外部访问、云端同步和多用户隔离属于未来产品阶段，届时必须在适配层和 Runtime 边界明确引入身份模型，不能把单用户假设扩散为不可迁移的业务规则。

## 八、V1 技术承载决策

V1 保持现有的 Node.js + TypeScript Runtime，不引入 Python 服务，也不采用 FastAPI。

```text
Next.js（React PWA + Route Handlers；仅本机回环地址）
  ↓
GrandEunuch Runtime（pi-agent-core + pi-ai）
  ↓
本地 SQLite（node:sqlite）
```

- Next.js 负责 React PWA、页面路由、本地 HTTP API、请求边界校验与静态资源交付，替代此前计划中的 Vite + Fastify；
- 现有 `pi-agent-core` / `pi-ai` 继续负责 Agent Loop、模型通信和工具调用；
- Memory、Wake、幂等、取消、遗忘及 occurrence 去重仍属于项目自有 Runtime，不委托给 Web 框架、前端状态库或 Agent SDK；
- 本地 MVP 维持单一 Node 进程，避免 Python/Node 双服务、跨进程调用和双重数据库边界；
- 云端阶段可在不改变上述 Runtime 语义的前提下，引入身份层、服务端数据库和独立 Runtime Worker / Scheduler；Next.js 继续承担 Web UI 与 API 边界。

聊天交互层计划使用 Vercel AI SDK UI，但仅作为 React 流式消息与交互状态的客户端库；它不拥有对话记录、Memory、Wake 或业务决策权。PWA 插件与具体配置将在客户端实现阶段确定。

## 九、V1 对话记录策略

V1 将原始对话消息**永久保存在本地 SQLite**，以便用户刷新或重启本地服务后继续查看对话。

- 不提供导出、会话列表、会话改名、单条删除或清空对话界面；
- 不把“从界面隐藏消息”错误表述为严格遗忘；
- `memory.forget` 的严格遗忘语义仍以 Runtime 契约为准，未来需单独设计其用户确认和对原始对话、长期记忆、索引与关联 Wake 的影响范围。

可以继续完成 Runtime 八工具、Wake 可靠性和测试，并以单用户本地部署、应用内提醒和本地持久对话为前提设计最小 Web API；不得因此让 Agent 或 Runtime 获得业务判断权。
