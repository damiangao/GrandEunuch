# 两周居住实验协议

> 目的：给"我想养一个活过时间的东西"这个假设一个可证伪的实验。
> 实验测的是**关系价值**，不是管道质量——bug 不算信号（见下）。

## 0. 入场的门槛（day 0 之前）

1. 冒烟清单跑通（六步，亲手操作，见 README 或对话记录）；
2. 烧机门全绿：`npm run build:runtime && node --env-file=.env scripts/burn-in.ts`
3. 评测矩阵全绿：`node --env-file=.env scripts/evals.ts`（30 场景，memory/wake/product × L1/L2/L3）
4. tracing 已装：每个 Run 都在 `run_traces` 表留底。

## 1. 怎么住

1. **真实地住**：所有值得记的都往里说——不许挑食（只喂"适合系统的内容"会污染实验）。
2. **设计冻结**：不写代码、不中途改设计。每次冒出"我真想给它加个 X"，记进冲动清单——**冲动清单就是需求清单**。
3. **摩擦日志**：遇到别扭当场记一行。格式（一行就够）：

```
时间 | 你期望什么 | 它做了什么 | bug 还是 concept
```

   - `bug` = 管道问题（搜不到明明在的、时间算错、报错）。进修复队列，**不算信号**。
   - `concept` = 产品摩擦（它该不该开口、该不该记、姿态对不对）。**这才算信号。**

4. 正常安排提醒、正常被它叫，别刻意测试它。

## 2. 观察什么（五类摩擦，各对应一个死因）

| 摩擦 | 问题 | 对应的死因 |
|---|---|---|
| 记入摩擦 | 想记但懒得说/说得别扭 | 饿死 |
| 取出摩擦 | 找不到、被过时内容淹没 | 沼泽 |
| 开口摩擦 | 该提醒没提醒 / 不该提醒打扰了 | 被炒 |
| 来源摩擦 | 它把推断说成你说的、历史被悄悄改 | 信任破产 |
| 在场感 | 你回来时它第一句话有没有用 | 降级成 app |

不看消息数、工具调用数——每个观察量必须挂在一个决策上。

## 3. 第 7 天：15 分钟中期检查

只看一件事：**记入摩擦**。饿死是第一死因，早发现早治。若记入摩擦 ≥ 5 条：暂停实验，把录入成本问题当第一个 bug 修掉再续。

## 4. 第 14 天：复盘会（约 1 小时）

议程就是未来"大扫除"仪式的第一次手动执行：

1. **修剪清单**：哪些该忘、哪些过时、哪些从未被想起？
2. **信错清单**：它这周信错了什么？（对照 run_traces 核实，摩擦日志的每条 bug/concept 都 join 回 trace）
3. **第一条链接修在哪**：按摩擦分布排序决定。

### 预 commit 的决策表

| 两周后看到 | 决定 |
|---|---|
| 来源摩擦 ≥ 1 次 | 停一切新东西，先加固写路径——本金坏了利息无从谈起 |
| 记入摩擦最多 | 第一条链接：降录入成本 |
| 取出摩擦最多 | 第一条链接：代谢（修剪/压缩） |
| 开口摩擦最多 | 第一条链接：唤醒的脾气调校 |
| 从未想要它主动开口 | 推送面降级，agent 半边冻结，纯拉取 |
| 几乎没用、日志空白 | 证伪分支：你想要的可能不是这个对象——这是有效信息，不是失败 |
| 用得自然、摩擦具体而稀 | 假设成立，按摩擦排序逐条长链接 |

## 5. 复盘后的产物

- 一份摩擦清单（带 bug/concept 标签，join 了 trace 证据）
- 一条被预 commit 的决策
- 冲动清单（实验期间没被满足的愿望，按渴望强度排序）

以上三样，就是"往中间长链接"的第一批原料。
